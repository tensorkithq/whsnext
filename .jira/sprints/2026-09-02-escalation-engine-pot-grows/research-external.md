# Research: external — 2026-09-02-escalation-engine-pot-grows

## Summary

- The design's load-bearing assumption is directionally supported by the literature: i2v models demonstrably prioritize the conditioning image and internal priors over text directives, and recent work argues the first frame acts as a "conceptual memory buffer" the model reuses throughout generation. A big pot in the seed frame persists better than a big pot described in prose.
- The same evidence cuts the other way: because image dominates prose, a ladder fragment asking the pot to *grow within a clip* is the weakest link. Escalation is most reliable when it happens at a seed-image boundary (or via an end-frame keyframe), not mid-clip via Environment/Action text.
- Frame chaining degrades: exposure bias compounds per link. Practitioners report visible identity/color drift by clip 3–5 and "significant" degradation around 10 iterations; standard mitigations are full-res frame extraction, re-anchoring to a reference image, frame cleanup before re-seeding, and first/last-frame (FLF) conditioning. fal exposes `end_image_url` on Seedance 2.0/2.5 and Kling O1/O3 — matching the "end_image_url keyframe bridges" item this repo already deferred.
- For "3 vote options, each a variation of the same beat": prompt-only JSON fails 1–20% depending on schema complexity; OpenAI-style strict structured outputs reach ~100% *syntactic* validity via constrained decoding but can still fill fields with plausible-wrong content. Whether Celeris supports `response_format: json_schema` is unknown (OpenAI-*compatible* ≠ structured-outputs support) — post-validation + one retry is the portable floor, and D-15 already establishes that retry pattern.
- Prior art validates the architecture: L4D's AI Director (system owns intensity, players influence flavor through behavior) and the academic "experience manager / drama manager" tradition both put pacing authority in a server-side system, not in the generative component. Hand-rolling the ladder as an Elixir module attribute is clearly fine; no library earns its keep here.

## Findings

### Standard Stack

**Core (what the design already uses, externally):**
- fal.ai i2v models (Seedance, Kling families) via `fal_ex` (locked D-11). Frame-chained i2v is the established "extend past clip length" pattern industry-wide ([HackerNoon](https://hackernoon.com/how-to-extend-an-ai-generated-video-clip-past-its-length-limit-without-the-drift), [OCDevel: last-frame seeding and FLF interpolation](https://ocdevel.com/podcaster/ai-video-generation/091f7362-02ec-4afa-a4ff-e30e004db6db)).
- OpenAI-compatible chat completions for the script engine (Celeris, locked D-05).

**Supporting (when to use):**
- **First/last-frame (FLF) conditioning** — fal exposes `end_image_url` on [Seedance 2.0 i2v](https://fal.ai/models/bytedance/seedance-2.0/image-to-video/api), [Seedance 2.5 i2v](https://fal.ai/models/bytedance/seedance-2.5/image-to-video/api), and [Kling O1 first-to-last-frame](https://fal.ai/models/fal-ai/kling-video/o1/image-to-video/api) / [Kling O3](https://fal.ai/models/fal-ai/kling-video/o3/standard/image-to-video); when both frames are given the model interpolates a trajectory between them instead of extrapolating freely. This is the strongest known mechanism for *forcing* a size-class transition to land: render a still of the next size class, hand it in as the end frame. (Repo already deferred exactly this: STATE.md "Deferred: end_image_url keyframe bridges".)
- **Negative prompts against shrinkage** — model-dependent, not portable: Kling exposes a dedicated `negative_prompt` field (default "blur, distort, and low quality"); Seedance 2.0 exposes neither negative prompt nor CFG scale — guards must be rewritten as inline prohibitions there ([fal: Seedance 2.0 vs Kling 3.0](https://fal.ai/learn/tools/seedance-2-0-vs-kling-3-0), [invideo on per-model negative-prompt handling](https://invideo.io/faq/how-do-negative-prompts-work-differently-in-kling-veo/)). Community guidance also treats negative prompts as quality guards (blur, morphing), not reliable semantic controls like "small pot" ([Artlist](https://artlist.io/blog/negative-prompts-ai-video/)).
- **VLM frame check** (detect a regressed pot before seeding the next clip) — a GPT-4o-class VLM on one extracted frame with a yes/no rubric is the established automated-QA pattern; a 2025 gameplay-QA study found single-run VLM judgments non-deterministic (median F1 0.79) with majority-vote-of-3 needed for stability ([arXiv 2508.04895](https://arxiv.org/html/2508.04895v1)). Cost is token-priced ($0.15/M input for gpt-4o-mini — [OpenAI pricing](https://developers.openai.com/api/docs/pricing)); one image + short rubric is fractions of a cent, latency typically a few seconds — but that lands on the critical path between vote lock and next clip dispatch.

**Alternatives (tradeoffs, not recommendations):**
- Longer-native-window models (fal hosts several) sidestep chaining entirely but conflict with the vote-per-clip format ([HackerNoon](https://hackernoon.com/how-to-extend-an-ai-generated-video-clip-past-its-length-limit-without-the-drift)).
- Image-edit round trip (edit the extracted frame to enlarge the pot, then i2v from the edited frame) puts escalation fully in pixels before generation — an extra model call per lock, but converts a prose hope into an image guarantee. Same family as practitioners' "re-mint the frame in image-to-image before chaining" ([Renoise guide](https://renoise.ai/guides/ai-video-extender)).

### Prompt-adherence reality (the load-bearing assumption)

- **Image conditioning dominates prose — supported.** The Focal Guidance paper states SOTA i2v models "struggle to maintain this delicate balance, frequently prioritizing the visual condition and internal priors over textual directives" ([arXiv 2601.07287](https://arxiv.org/pdf/2601.07287)). "First Frame Is the Place to Go" argues video models treat the first frame as a "conceptual memory buffer that stores visual entities for later reuse during generation" ([arXiv 2511.15700](https://arxiv.org/html/2511.15700)) — direct support for "escalation baked into pixels self-persists."
- **Prose control of object scale is measurably weak.** Fine-grained i2v evaluation of complex instruction following scores even top models (Kling 2.6) ~3.13/5 on prompt-following for entity-size tasks ([Seedance 2.0 tech report, arXiv 2604.14148](https://arxiv.org/pdf/2604.14148)) — i.e., "the pot stands chest-high" in the Action section is probabilistic, consistent with this repo's own adherence logs cited in the brief.
- **Implication (evidence, not recommendation):** the ladder fragment's reliable job is *describing what's already in the seed frame* (keeping the model from fighting the image) and *steering the new action's flavor*; its unreliable job is *introducing a size change the seed frame doesn't show*. TIP-I2V's analysis of a million real i2v prompts likewise finds users lean on the image for content and the text for motion ([arXiv 2411.04709](https://arxiv.org/abs/2411.04709)).

### Monotonic progression across chained clips

- **Drift is the default, not the exception.** Chaining last frames creates exposure bias — each link is conditioned on a model-made frame, and errors compound; quality "significantly degrades after around 10 iterations" ([FramePack project page](https://lllyasviel.github.io/frame_pack_gitpage/), [HackerNoon](https://hackernoon.com/how-to-extend-an-ai-generated-video-clip-past-its-length-limit-without-the-drift)). A worked example shows color/identity drift by the third extension (cloak darkened, torchlight amber→white).
- **Practitioner playbook when a frame undoes progress:** (1) extract the last frame at full resolution, never a compressed preview; (2) clean/upscale ("re-mint") the frame in image-to-image before seeding the next clip; (3) re-anchor to a canonical reference image at every extension rather than trusting the chain; (4) color-match links in the edit; (5) cap pure chaining at ~2 extensions before a hard reset ([Renoise](https://renoise.ai/guides/ai-video-extender), [MagicHour](https://magichour.ai/blog/how-to-extend-a-video-with-ai), [MobileMall on character drift by clip five](https://mobilemall.co/blog/your-ai-video-character-looks-fine-in-clip-one-and-like-somebody-else-by-clip-five/), [Hailuo](https://hailuoai.video/pages/blog/how-to-extend-video-with-ai)).
- **Keyframe ladders:** FLF ("start-end frame") generation is the documented tool for transitions where "both start and end states matter" — timelapse transformations and morphs are its named use cases ([fal Kling O1 docs](https://fal.ai/docs/model-api-reference/video-generation-api/kling-video-o1-image-to-video), [Kling start/end-frame guide](https://kling.ai/quickstart/ai-video-start-end-frames)). A pot growing one size class per clip is literally a stepwise timelapse.
- **Detection:** VLM check of the extracted frame ("is the pot at least waist-high relative to Amaka? yes/no") — see Standard Stack above for reliability (F1 0.79 single-run, majority-vote stabilizes) and cost. No off-the-shelf "monotonic object-scale checker" exists; it's a rubric prompt.

### LLM structured-output discipline (3 vote options, one beat)

- Prompt-only/few-shot JSON: historical failure rates 5–20% by schema complexity; well-tuned few-shot gets to ~1% ([Tensoria](https://tensoria.fr/en/blog/structured-outputs-llm-production)). OpenAI's own benchmark: gpt-4o without constrained decoding hit 93% schema compliance; with strict structured outputs, 100% ([OpenAI announcement](https://openai.com/index/introducing-structured-outputs-in-the-api/)).
- Constrained decoding guarantees *shape*, not *semantics*: when the natural next token is masked out, models can fill required fields with plausible-but-wrong values ([Let's Data Science](https://letsdatascience.com/blog/structured-outputs-making-llms-return-reliable-json)). "Three options that are each a variation of the same beat" is a semantic constraint no schema can express — it needs post-validation (count == 3, each option references the locked escalation form) regardless of transport.
- Celeris compatibility unknown: OpenAI-compatible chat completions (D-05) does not imply `response_format: {type: "json_schema", strict: true}` support — many compatible endpoints only honor `json_object` or nothing. Validate-and-retry-once (the D-15 pattern) is the transport-independent floor; the Elixir `instructor` / `InstructorLite` libraries exist precisely to package that loop (Ecto-schema validation + `max_retries`) over OpenAI-compatible APIs ([instructor_ex](https://github.com/thmsmlr/instructor_ex), [InstructorLite announcement](https://elixirforum.com/t/instructorlite-structured-outputs-for-llms-a-tinkering-friendly-fork-of-instructor/65898)).

### Prior art: server-authoritative escalation

- **L4D AI Director** — the canonical citation. The system tracks per-player "intensity," owns pacing (Build Up → Peak → Relax), and decides when to spawn/relent; players never vote on *whether* tension escalates, only shape it through behavior. Primary source: Mike Booth (Valve), "The AI Systems of Left 4 Dead" ([slides PDF](https://steamcdn-a.akamaihd.net/apps/valve/2009/ai_systems_of_l4d_mike_booth.pdf); accessible summaries: [L4D wiki](https://left4dead.fandom.com/wiki/The_Director), [CenterConsulting](https://www.centerconsulting.com/ai-library/concepts/l4d-director)). Validates "system decides intensity, input decides flavor" as a shipped, beloved pattern.
- **Experience managers / drama managers** — the academic frame: an integrated agent that "controls non-player elements of the story world and directs them in service of a particular narrative experience," balancing authorial structure against player agency. Riedl & Bulitko, "Interactive Narrative: An Intelligent Systems Approach," AI Magazine 34(1), 2013 ([AAAI](https://ojs.aaai.org/aimagazine/index.php/aimagazine/article/view/2449)); see also the [drama-management survey](https://www.researchgate.net/publication/228926772_A_survey_and_qualitative_analysis_of_recent_advances_in_drama_management). The consistent lesson: pacing authority lives in a deterministic manager; generative/agent components execute under it — same shape as `absurdity_level` in EpisodeServer rather than in the script engine.
- Nothing found combining this with *generative video* specifically; the pattern transfer is by analogy, not precedent (noted under Open questions).

### Don't-hand-roll check (external half)

- **Ladder table: hand-rolled is correct.** A fixed L0–L5 fragment table is static data; Elixir has EEx built in for interpolation and the [LangChain Elixir `PromptTemplate`](https://langchain.hexdocs.pm/LangChain.PromptTemplate.html) is itself just EEx with bookkeeping — adopting the `langchain` hex package for six strings adds a dependency and its chat-model abstractions the repo already bypasses (D-05 raw Celeris). No prompt-laddering/scheduling library exists in the Elixir ecosystem; prompt scheduling as a concept lives in SD-webui tooling, not server frameworks.
- **Structured-output retry loop: a candidate, not a need.** `instructor` (hex) packages schema-validate-and-retry over OpenAI-compatible APIs; the repo's existing Celeris retry (D-15) already covers the one-retry case, so the library only pays off if option-generation validation grows Ecto-schema-shaped.

### Common Pitfalls

1. **Mid-clip growth via prose silently fails.** i2v models favor the conditioning image and internal priors over text ([arXiv 2601.07287](https://arxiv.org/pdf/2601.07287)); entity-size instruction-following scores ~3/5 even on top models ([arXiv 2604.14148](https://arxiv.org/pdf/2604.14148)). Warning sign: emitted clip shows the L(n) pot doing the L(n+1) action, or no size change at all. The ladder fragment alone does not guarantee the bump lands in pixels.
2. **Chained-frame drift compounds and can *undo* escalation.** Exposure bias degrades chains — visible drift by extension 2–3, severe by ~10 links ([FramePack](https://lllyasviel.github.io/frame_pack_gitpage/), [HackerNoon](https://hackernoon.com/how-to-extend-an-ai-generated-video-clip-past-its-length-limit-without-the-drift), [MobileMall](https://mobilemall.co/blog/your-ai-video-character-looks-fine-in-clip-one-and-like-somebody-else-by-clip-five/)). A 6-level episode is ~6+ links (scenes plus bridges) — inside the danger zone. Warning signs: color/contrast shift, pot proportions regressing toward "normal kitchen pot" (the model's prior).
3. **Negative-prompt anti-shrinkage isn't portable.** Kling has a dedicated `negative_prompt` param; Seedance 2.0 has none ([fal comparison](https://fal.ai/learn/tools/seedance-2-0-vs-kling-3-0)). Any "no small pot" guard hard-coded as an API param breaks on model swap; inline prohibitions in the main prompt are the only cross-model form, and negative semantics in positive prompts can backfire (mentioning "small pot" at all puts it in the conditioning).
4. **t2v fallback breaks the pixel chain.** The repo's own fallback path (frame extraction fails → t2v, per STATE.md) regenerates from prose only — precisely the modality with weak size adherence. At L4 the fallback clip has nothing but the ladder fragment holding up a car-sized pot. (Inference from cited adherence evidence + repo decision; no external source addresses this combination.)
5. **Structured outputs guarantee JSON, not "three variations of one beat."** Constrained decoding can produce schema-valid but semantically off options (wrong escalation form, duplicate options) ([Let's Data Science](https://letsdatascience.com/blog/structured-outputs-making-llms-return-reliable-json)); prompt-only JSON fails 1–20% ([Tensoria](https://tensoria.fr/en/blog/structured-outputs-llm-production), [OpenAI](https://openai.com/index/introducing-structured-outputs-in-the-api/)). Warning sign: options that name different beats ("stir with paddle" / "add more pepper" / "leave the kitchen") — the vote then decides *whether*, not *how*, violating the design's core rule.
6. **VLM regression checks are non-deterministic.** Single-run VLM frame judgments vary across identical runs (median F1 0.79; majority-of-3 needed for stability — [arXiv 2508.04895](https://arxiv.org/html/2508.04895v1)). A flaky "pot too small" verdict that triggers regeneration adds cost and lock-to-clip latency for false positives.

### SOTA Updates

- **Old:** single-image i2v + prose to steer outcomes. **Current (2025–26):** first/last-frame conditioning as a first-class API param on fal-hosted Seedance 2.x and Kling O1/O3/2.1-Pro ([fal Seedance 2.0 api](https://fal.ai/models/bytedance/seedance-2.0/image-to-video/api), [fal Kling O1](https://fal.ai/models/fal-ai/kling-video/o1/image-to-video/api)) — transitions with defined end states moved from "hope the prompt works" to "interpolate between two constraints."
- **Old:** "output valid JSON" + few-shot (5–20% failure). **Current:** strict schema constrained decoding, ~100% syntactic validity where supported (OpenAI, Aug 2024 onward — [announcement](https://openai.com/index/introducing-structured-outputs-in-the-api/)); support across OpenAI-*compatible* endpoints remains inconsistent.

## Open questions

- Does Celeris (`celeris-1`) honor `response_format` at all (`json_object`? `json_schema` strict)? Needs a one-call probe; determines whether option-generation relies on post-validation alone.
- Which exact fal model IDs does the pipeline currently call, and do those specific endpoints expose `end_image_url` / `negative_prompt`? (Sibling `codebase` agent's territory; the parameter surface differs per model family.)
- No citable precedent found for a server-authoritative escalation ladder driving *generative video* specifically — L4D/drama-manager evidence transfers by analogy only.
- Per-frame VLM check cost is negligible, but end-to-end latency on the lock→dispatch path (upload + inference + majority-vote×3 if needed) is unmeasured for this stack.
- Whether an image-edit "grow the pot, then seed i2v" round trip beats FLF `end_image_url` on quality/cost is untested anywhere findable; both are plausible, neither benchmarked for stepwise object growth.
